What it is
A place for every useful agent.
If an agent helps someone do something real, it belongs here — on-chain or off-chain. Think stablecoin payments, DeFi strategies, or a wallet security guard; or an inbox assistant, a research agent, a support bot, or a direction no one has tried yet. No required stack, no required zkVerify. Just show the agent working and explain who it helps.
01
Pick a real problem
Choose the people or workflow your agent serves. A clear use case matters more than fitting a preset category.
02
Show the agent working
Share a public link and endpoint so reviewers can understand the build and see what it can do.
03
Add proof if it helps
A thoughtful zkVerify use case can strengthen your entry. If you include a proof, explain exactly what it establishes.
What to include
Submission requirements
AGENT LINK
A public repository, demo, or write-up showing the agent you built.
PUBLIC ENDPOINT
A public HTTPS endpoint for your agent, as requested in the submission form.
USE CASE
Explain the problem, who the agent helps, and what it actually does — any domain, on-chain or off-chain.
BUILD CONTEXT
Briefly describe how the agent works and the key decisions behind it.
ZKVERIFY (OPTIONAL)
If zkVerify strengthens your agent, explain the checkable claim and add a proof reference when available.
How work is judged
What reviewers look for
Useful problem
Show a clear need, who the agent helps, and why its work matters.
Working implementation
Make it possible to understand what you built and see the agent in action.
Clear explanation
Explain the workflow, key choices, and what the agent can and cannot do.
Verifiability (optional plus)
If zkVerify makes an important claim checkable, explain how it helps. Agents without zkVerify remain eligible.
Bonus (public share)
Just share your build publicly — what the agent is and a public demo. That's it.
Inspiration
Many use cases are welcome
These are starting points, not a checklist. Submit an agent for any real problem — on-chain or off-chain; verifiability with zkVerify is one optional direction.
zkTLS — prove what your agent saw on the web
Suggested direction
A strong optional way to earn the verifiability plus — and it works for off-chain agents too: use zkTLS to turn a real HTTPS or API response your agent relied on into a zkVerify-checkable claim, without revealing the full payload. It is a suggestion, not a requirement.
